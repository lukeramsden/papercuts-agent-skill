# Custom storage adapters

The lifecycle service depends on four operations, not a specific cloud. An
adapter factory receives a dictionary and returns an object with this interface:

```python
class Storage:
    def read(self, key: str) -> tuple[bytes, str] | None:
        """Bytes and opaque revision; None only for a genuinely absent object."""

    def write(self, key: str, data: bytes, expected: str | None) -> str:
        """Return new revision. None = create only; otherwise exact revision match."""

    def list(self, prefix: str) -> list[str]:
        """Every key below prefix, relative to the configured storage root."""

    def delete(self, key: str, expected: str) -> None:
        """Delete only this revision. Used for diagnostic objects, not records."""
```

## Required semantics

- Import `Conflict` and `PapercutsError` from `papercuts_lib.model`.
- `write(..., expected=None)` is an atomic **create-if-absent**, not overwrite.
- `write(..., expected=REV)` atomically compares and replaces. Raise `Conflict`
  on a mismatch. A client-side read followed by unconditional PUT is not enough.
- Every change must invalidate the old revision. Keep revisions opaque to callers.
- Reads must return matching bytes/revision, never bytes from one version and a
  token from another. Enforce the 1 MiB record limit before large downloads.
- Listing must exhaust all pages; do not silently truncate. Return relative keys,
  with a trailing-slash prefix interpreted as a directory boundary.
- Missing objects are `None`. Auth, missing bucket/database, network, corruption
  and permission errors are exceptions. Never convert them to absence/empty list.
- Diagnostic deletion is conditional too. Never delete an unexpected revision.
- Bound retries and timeouts; protect credentials; use verified TLS for networks.
  Do not put token-bearing provider error messages in agent output.
- Never execute or interpret record content. Keys are generated by the service;
  still validate them with `papercuts_lib.storage.check_key`.

The adapter receives keys like `my-project/v1/records/pc_...md`. Its own bucket,
filesystem directory or tenant root is configured in the factory, not inferred
from a repository. Namespaces are not an authorisation mechanism.

## Configuring a trusted factory

Write a private config outside the repository:

```json
{
  "schema_version": 1,
  "namespace": "my-project",
  "author": "team-agent",
  "source": "agent",
  "adapter": "my_papercuts_backend:create",
  "options": {
    "tenant": "example"
  }
}
```

Install that module into the Python environment used by the launcher. Then:

```bash
./papercuts --config /private/custom.json doctor --offline
./papercuts --config /private/custom.json doctor --write-test
./papercuts --config /private/custom.json add 'A small annoyance.'
```

Only configure modules you have reviewed and trust. Factories are executable
Python, not sandboxed configuration. The CLI never installs/imports a module
named by a papercut and never discovers config from the current repository.
`PAPERCUTS_STORAGE` overrides and disables the configured adapter; unset it when
using a custom backend. No secret values belong in `options`; use a runner
identity or private credential store managed by the adapter.

## Included SQLite reference adapter

`papercuts_lib/sqlite_adapter.py` is a working, standard-library-only example.
It stores Markdown bytes in a SQLite table, uses transaction/revision-checked
updates, and needs no package install. It is not offered by the interactive setup
wizard; configure it explicitly:

```json
{
  "schema_version": 1,
  "namespace": "my-project",
  "adapter": "papercuts_lib.sqlite_adapter:create",
  "options": {
    "path": "/absolute/private/path/papercuts.sqlite3"
  }
}
```

Use an absolute path on a persistent **single-host local disk**, not NFS or an
object-store mount. New databases use mode 600 and parent directories 700;
existing parent permissions are not changed. SQLite transactions provide
compare-and-swap for multiple processes on that host. The adapter does not add
an indexed search API; the generic service still scans records. Credentials
are irrelevant; database contents are plaintext.

The example illustrates how to build a transactional adapter. For Postgres,
replace the SQLite connection and queries with equivalent conditional SQL,
add connection pooling/tenant authorisation, and preserve the contract. For
Azure Blob or an HTTP service, use native ETag conditions. These alternatives
are **not implemented here**.

## Testing an adapter

Run its contract tests without real credentials. Cover:

1. Empty list and absent read.
2. Create then matching bytes/revision read.
3. Duplicate create rejected without changing data.
4. Correct revision update succeeds; stale revision update fails.
5. At least two concurrent processes attempt one revision; exactly one wins.
6. Wrong-revision delete fails; correct-revision diagnostic delete succeeds.
7. Full pagination and namespace/prefix isolation.
8. Permission/network errors are not converted into empty results.
9. Corrupt/oversized records fail visibly.
10. No secret values appear in errors.

Use the bundled tests and `doctor --write-test` as starting points. A live probe
is necessary for each actual S3-compatible service; mocked protocol tests cannot
prove that a server enforces its preconditions. Do not run tests against someone
else's real backlog or create cloud resources without permission.
